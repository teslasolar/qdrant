                         DATA FLOW EXAMPLE
================================================================================

Patient Scan Workflow (All Standards Working Together):

1. ORDER (L4 - HIS)
   → Patient order created in HIS
   → ISA-95: L4 → L3 communication

2. WORKLIST (L3 - RIS/PACS)
   → Study appears on modality worklist
   → Protocol selected
   → ISA-95: L3 → L2 communication

3. OPERATOR (L2 - HMI)
   → Opens ISA-101 Overview Screen
   → Sees CT Scanner 1 PackML state = "Idle"
   → Clicks to Detail Screen (ISA-101)
   → ISA-88 hierarchy navigation: Area → Cell → Unit

4. PREPARATION (L1 - Controller)
   → CT Scanner receives parameters
   → PackML state: Idle → Starting
   → Safety checks via ISA-88 phases
   → ISA-95: L2 → L1 communication

5. EXECUTION (L0-L1)
   → Operator sends Start command (PackML)
   → PackML state: Starting → Execute
   → ISA-88 procedural control:
       Procedure: CT Head Scan
         └─ Unit Procedure: Acquire Images
             └─ Operation: X-Ray Exposure
                 └─ Phase: Activate Generator
   → Physical process operates (L0)

6. MONITORING (All Levels)
   → OPC-UA: State published to all subscribers
   → MQTT: spBv1.0/.../DDATA/Gateway/CT_1
      Metrics: {PackML.State: "Execute", Process.KVP: 120, ...}
   → ISA-101 HMI: Real-time display updates
   → Historian: Tags logged
   → Cloud: IoT dashboard shows scanner active

7. COMPLETION (L1 → L3)
   → Scan completes
   → PackML state: Execute → Completing → Complete
   → Images sent to PACS (L3)
   → ISA-95: L1 → L2 → L3 data flow

8. REPORTING (L3 → L4)
   → Radiologist reviews (L3)
   → Report created
   → Results to HIS (L4)
   → ISA-95: L3 → L4 communication

9. RESET (L1)
   → Operator sends Reset command (PackML)
   → PackML state: Complete → Resetting → Idle
   → ISA-88 hierarchy ready for next patient
   → OPC-UA & MQTT publish state change

Throughout: ISA-101 provides consistent, high-performance visualization
           ISA-88 provides equipment and procedural organization
           PackML provides standard equipment control
           ISA-95 defines communication architecture
           OPC-UA & MQTT enable interoperable data exchange


================================================================================
                    KEY INNOVATION: COMPOSABILITY
================================================================================

Each standard is independent but designed to compose:

ISA-88 Equipment Hierarchy PROVIDES → Equipment paths
PackML State Machine      CONSUMES → Equipment paths
                         PROVIDES → State tags

MQTT/Sparkplug B         CONSUMES → State tags
                         PROVIDES → IIoT topics

OPC-UA                   CONSUMES → Equipment hierarchy + State tags
                         PROVIDES → Interoperable interface

ISA-101 HMI              CONSUMES → Equipment hierarchy + PackML states
                         PROVIDES → Operator interface

ISA-95 Architecture      PROVIDES → System organization
                         CONSUMES → All other standards
                         MAPS → Standards to functional levels

Result: Standards compose into complete, integrated systems
